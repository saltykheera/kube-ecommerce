# WooCommerce Hosting Platform with Team MCP Gateway on Kubernetes

A production-grade, stateful Kubernetes deployment hosting WooCommerce with an integrated Model Context Protocol (MCP) Gateway layer for AI agents (Claude Code, Cursor, MCP Inspector, and Dashboard Chat).

---

## Quick Reference: Starting and Stopping

### To Start / Resume the Platform
```bash
./scripts/start.sh
```
*Checks Docker, resumes or initializes the k3d cluster, verifies all 8 pods are Ready, and displays active endpoints and credentials.*

### To Stop / Pause the Platform
```bash
./scripts/stop.sh
```
*Safely pauses the cluster containers. CPU & RAM are immediately freed up, while **all WooCommerce products, orders, database tables, and persistent storage (PVCs) remain 100% saved on disk**.*

## Small EC2 Kubernetes Demo

For a sequential demo, use the optional [demo values](helm/ecommerce-stack/values-demo.yaml).
This keeps all eight services, Kubernetes ingress, persistent volumes, and NetworkPolicies.
It requests 656 MiB of application memory, compared with 992 MiB by default, and tunes
database caches and connections plus Apache/PHP worker count to reduce actual usage.
These requests are scheduling reservations, not measured usage or a guarantee of capacity.

Target a **2-vCPU, 2-GiB RAM instance with at least 20 GiB disk** (for example, t3.small).
This is a constrained test target; K3s and Ubuntu also need memory. Keep 4 GiB if the
actual demo produces OOM kills or node memory pressure. The existing 1-GiB VM is below
the documented K3s server minimum. Build images outside the small VM and import matching
architecture images into K3s to avoid build-time memory spikes and duplicate build caches.

After preparing K3s and importing images, apply the demo profile last:

```bash
helm upgrade --install ecommerce-stack ./helm/ecommerce-stack \
  -f ./helm/ecommerce-stack/values-aws.yaml \
  -f ./helm/ecommerce-stack/values-demo.yaml \
  -f ./cloud-secrets.json \
  --wait --timeout 10m
kubectl get pods
kubectl top nodes
kubectl top pods
```

`values-aws.yaml` supplies the instance's ingress domains and is generated by the AWS
deployment script. That script currently builds images on the VM; it needs an external
build/import workflow before being used on this smaller target. Keep the existing PVC
sizes when upgrading an installed release; Kubernetes cannot shrink PVCs.
Run the upgrade on the configured VM, where `cloud-secrets.json` preserves the deployed
database passwords and API keys. See [EC2 deployment details](EC2-DEPLOYMENT.md) for
the current host, access links, and update instructions.
After WooCommerce setup, verify storefront access, dashboard login, and an MCP tool call
while checking memory and pod restarts. `kubectl top` requires the metrics-server to be ready.

## Live Endpoints & Default Credentials

| Service | Local URL | Role | Credentials |
| :--- | :--- | :--- | :--- |
| **WooCommerce Store** | `http://store.local` | Public storefront & WP Admin | `admin` / `AdminSecurePassword123!` |
| **PostHog Dashboard** | `http://dashboard.local` | Team & MCP Server Management | `admin@ecommerce.local` / `AdminSecurePassword123!`<br/>`member@ecommerce.local` / `MemberSecurePassword123!` |
| **Central MCP Gateway** | `http://gateway.local/mcp` | Unified Streamable HTTP MCP Endpoint | `Authorization: Bearer <mcp_live_...>` |
| **Gateway Health Check**| `http://gateway.local/health` | HTTP Liveness / Probe | *Public* |

> [!NOTE]
> Ensure local domain resolution is configured in `/etc/hosts`:
> ```bash
> sudo sh -c 'echo "127.0.0.1   store.local gateway.local dashboard.local" >> /etc/hosts'
> ```
